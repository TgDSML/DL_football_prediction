Pipeline Deduplication and Leakage Audit
========================================

Scope
-----

builders. No code was deleted.

1. Duplicate ML Baselines
-------------------------

Canonical baseline: src/models/ml_baselines.py

- Models trained: dummy_most_frequent, logistic_regression, random_forest,
  gradient_boosting, xgboost.
- Inputs:
  - Team perspective default: data/processed/splits/train.csv, val.csv, test.csv.
  - Fixture perspective optional: data/processed/fixture_level/train.csv, val.csv,
    test.csv.
- Target:
  - Team perspective: target = 0 win, 1 draw, 2 loss from the team's perspective.
  - Fixture perspective: target = 0 HomeWin, 1 Draw, 2 AwayWin.
- Metrics: accuracy, balanced accuracy, macro F1, log loss where available,
  confusion matrix, classification report.
- Latest reported team performance:
  - Best accuracy: xgboost, 0.5157.
  - Best macro F1: logistic_regression, 0.4391.
- Latest reported fixture performance:
  - Best accuracy: random_forest, 0.5211.
  - Best macro F1: logistic_regression, 0.4237.
- Leakage/reproducibility:
  - Uses src/utils/data_utils.py validation to reject direct current-match
    leakage columns.
  - Reports split date ranges and feature columns.
  - Reproducible through README-documented commands.

Legacy weighted baseline: models/ml_models.py

- Models trained: logistic_regression_weighted, svm_rbf_weighted,
  xgboost_weighted, ensemble_avg_proba.
- Inputs: data/processed/X_train.csv, X_val.csv, X_test.csv and y_train.csv,
  y_val.csv, y_test.csv generated by the older split_for_ml.py path.
- Target: first column of y_* CSVs; effectively the older team-perspective target.
- Metrics: validation/test accuracy, macro F1, classification reports, confusion
  matrices, prediction CSVs, model config JSON.
- Latest reported performance: no artifacts/ml_artifacts/ml_run_report.txt or
  model_comparison_weighted.csv exists in this checkout, so current performance
  is not verifiable from committed outputs.
- Leakage/reproducibility:
  - Depends on older data/processed/train_features.csv path.
  - Does not use src/utils/data_utils.py leakage validation.
  - Does not document chronological split boundaries in the report builder.

Legacy dummy baseline: models/baseline_model.py

- Model trained: sklearn DummyClassifier(strategy="stratified").
- Inputs: data/interim/train_processed.csv and data/interim/test_processed.csv.
- Target: FTR.
- Metrics: accuracy, macro F1, weighted F1, class priors, confusion matrix,
  classification report.
- Latest reported performance: no artifacts/baseline/stratified_test_metrics.txt
  exists in this checkout.
- Purpose overlap: only a naive floor, already superseded by the dummy baseline
  inside src/models/ml_baselines.py.

ML Baseline Recommendation
--------------------------
Keep src/models/ml_baselines.py. It is stronger, simpler to run, documented,
supports both team and fixture baselines, has committed reports, and validates
direct leakage columns.

Archive/remove later:
- models/ml_models.py
- models/baseline_model.py
- data/processed/split_for_ml.py if no remaining workflow uses X_*/y_* CSVs.
- data/interim/interim_encode.py and data/processed/team_centric.py only if the
  team agrees to remove the older interim pipeline.


2. Sequence Builder Inventory
-----------------------------

Canonical raw sequence builder: src/features/sequences.py + scripts/build_sequences.py

- Source input: raw season CSVs loaded through src/features/build_team_features.py
  plus data/raw/splits/train.csv and val.csv to define chronological split bounds.
- Target: TARGET_MAP = {"H": 0, "D": 1, "A": 2}.
- Variants:
  - home_only: previous home-team matches only.
  - home_away: previous home-team and away-team histories concatenated per timestep.
- Feature modes:
  - raw: 17 features per team timestep, 34 features for home_away.
  - raw_plus_rolling: 80 features per team timestep, 160 for home_away.
- Important features:
  - raw match-history stats from prior games: was_home, points, goals_for,
    goals_against, goal_diff, shots, shots on target, corners, cards, rest_days,
    team_elo.
  - optional shifted rolling aggregates and streak/form features.
- Output tensor shape:
  - X: (num_samples, sequence_length, num_features)
  - y: (num_samples,)
  - Existing report examples:
    - home_away seq10 raw_plus_rolling train=(6154, 10, 160),
      val=(1500, 10, 160), test=(1860, 10, 160).
    - home_away seq50 raw_plus_rolling train=(5014, 50, 160),
      val=(1400, 50, 160), test=(1753, 50, 160).
- Saved file paths:
  - data/processed/sequences/home_only_train.npz, *_metadata.csv.
  - data/processed/sequences/home_away_train.npz, *_metadata.csv.
  - sequence-length variants use e.g. home_away_seq10_train.npz.
  - raw_plus_rolling writes under data/processed/sequences/raw_plus_rolling/.
- Current checkout note: generated .npz files are ignored and absent; metadata
  files and reports are present.
- Dependents:
  - scripts/train_rnn_from_scratch.py
  - scripts/train_dual_rnn_from_scratch.py
  - scripts/train_gru_from_scratch.py
  - tests/test_sequence_features.py

3. Leakage Audit
----------------

Canonical raw sequence builder: src/features/sequences.py

- Leakage risk: low.
- Safe to keep: yes.
- Positive checks:
  - Current target fixture stats are not read into the target sequence. The
    sequence windows are pulled from strict-prior team history.
  - Strict prior windows use Date < target_date at src/features/sequences.py:404.
  - home_only raises if history_end_date is not before fixture.Date at
    src/features/sequences.py:437-441.
  - home_away raises if either home or away history end is not before the target
    fixture at src/features/sequences.py:510-515.
  - Rolling features are shifted by one match before rolling at
    src/features/sequences.py:268.
  - Elo ratings are pre-match because src/features/elo.py records home_elo and
    away_elo before updating ratings at src/features/elo.py:45-71.
  - Split assignment is by target fixture date, using raw train/val boundaries.
  - Metadata and y labels are appended in the same loop and then sorted by Date;
    arrays are also appended in chronological fixture order, so alignment is
    preserved under the current sorted input.
- Suspicious/weak points:
  - src/features/sequences.py:461 and 541 sort metadata by Date after arrays are
    already stacked. Because fixture iteration is already Date sorted this is
    currently safe, but adding a stronger alignment test would reduce risk.
  - Same-day fixtures are excluded from history by Date < target_date. This is
    conservative and avoids same-day ordering ambiguity, but may omit valid prior
    same-day matches if they ever existed for a team.

Standalone raw sequence builder: data/processed/raw_sequence_engineering.py

- Leakage risk: low for its raw/home-away logic, medium as a project dependency
  because it duplicates canonical code and can drift.
- Safe to keep: safe only as an archived compatibility path; not recommended as
  default.
- Positive checks:
  - Strict prior windows use Date < target_date at data/processed/raw_sequence_engineering.py:444.
  - Raises if current/future matches enter home_only/home_away windows at
    data/processed/raw_sequence_engineering.py:487-489 and 517-520.
  - Rolling features are shifted at data/processed/raw_sequence_engineering.py:362.
  - Pre-match Elo is computed before rating updates at
    data/processed/raw_sequence_engineering.py:186-225.
- Suspicious/weak points:
  - It duplicates src/features/sequences.py and has a different default output
    directory and default feature mode. This increases drift and reproducibility
    risk.
  - It has its own Elo implementation instead of using src/features/elo.py.

Feature-derived CNN sequence builder: data/processed/sequence_engineering.py

- Leakage risk: medium.
- Safe to keep: not as default. It is acceptable only as a legacy reproduction
  path if its upstream data/processed/train_features.csv generation is retained
  and tested.
- Positive checks:
  - The builder creates a sequence before appending the current match vectors to
    match_history at data/processed/sequence_engineering.py:256-302.
  - Metadata records whether home/away history ends before target at
    data/processed/sequence_engineering.py:285-290.
  - The upstream feature_creation_split.py computes features before
    update_after_match, so its per-row engineered features are intended to be
    pre-match.
- Suspicious/weak points:
  - data/processed/sequence_engineering.py:285-290 records leak checks but does
    not raise on failure.
  - It depends on older generated train_features.csv/val_features.csv/test_features.csv
    that are not part of the current README canonical path.
  - It builds sequences from already-engineered target-row feature vectors,
    which is harder to audit than raw match history.
  - It keeps state across train, val, and test in process_one_sequence_length.
    Chronologically this is desirable, but it assumes the split files are
    processed in order and that no shuffled split file is supplied.
  - It writes NPZ files beside data/processed/sequence_engineering.py while
    metadata goes to artifacts/cnn/k_*, making reproducibility and cleanup harder.


4. Sequence Builder Comparison
------------------------------

| Criterion | src/features/sequences.py | data/processed/raw_sequence_engineering.py | data/processed/sequence_engineering.py |
| --- | --- | --- | --- |
| Feature richness | raw or raw_plus_rolling | raw or raw_plus_rolling | engineered rolling/context/prior-season features |
| Simplicity | Best: canonical module and CLI | Similar logic but duplicate | More moving parts and split artifact conventions |
| Leakage risk | Low | Low/medium operational drift | Medium |
| RNN/GRU compatibility | Direct default | Not used by scratch RNN/GRU | CNN-only legacy loader |
| CNN compatibility | Needs loader switch to src/raw_dataset_cnn or shared loader | Current raw CNN/CNN+LSTM path | Current older CNN path |
| Reproducibility | README documented, tested | Not README canonical | Older path, missing generated artifacts |
| Existing performance | Best raw RNN accuracy 0.5204; best raw RNN macro F1 0.4452; best raw GRU macro F1 0.4549 | No separate current report found | Older CNN reports not present in outputs/reports |
| raw_plus_rolling performance | Best reported accuracy 0.4855, macro F1 0.4519; does not beat raw sequence defaults | Same concept, duplicate | Not comparable |

Performance/reliability conclusion:
- Default sequence builder should be src/features/sequences.py.
- Default representation should be raw home_away, sequence length 10 for
  accuracy-oriented RNN runs, with class weighting when optimizing macro F1.
- raw_plus_rolling should remain optional for controlled comparisons because it
  did not beat raw sequence accuracy or best raw GRU macro F1 in the existing
  report.


5. Cleanup Recommendation
-------------------------

ML baseline to keep:
- src/models/ml_baselines.py
- src/models/baselines.py only if imported by config/training experiments; it is
  a small model factory and not a competing pipeline.

ML baseline to archive/remove later:
- models/ml_models.py
- models/baseline_model.py
- data/processed/split_for_ml.py if X_*/y_* CSV generation is no longer needed.
- data/interim/interim_encode.py and data/processed/team_centric.py if the old
  interim workflow is formally retired.

Sequence builder default:
- src/features/sequences.py through scripts/build_sequences.py.

Sequence builder to remove/archive or keep optional:
- Archive/remove data/processed/raw_sequence_engineering.py after migrating
  src/raw_dataset_cnn.py and raw CNN/CNN+LSTM scripts to consume
  data/processed/sequences from the canonical builder.
- Archive/remove data/processed/sequence_engineering.py and src/dataset_cnn.py
  if older CNN experiments are not required for reproducibility.
- Keep raw_plus_rolling as an optional feature mode inside src/features/sequences.py.

Files/scripts/tests that need updating before deleting paths:
- README.md: remove legacy CNN feature-derived instructions if that path is
  retired; document canonical sequence artifacts for CNN too.
- src/raw_dataset_cnn.py: point default data_dir to data/processed/sequences or
  merge loader behavior with src/dataset_cnn.py.
- scripts/cnn_raw_logic.py, scripts/cnn_raw_sweep.py,
  scripts/raw_cnn_sweep_lr_dropout_batchsize.py, scripts/train_cnn_lstm.py,
  scripts/train_cnn_lstm_2.py: update DATA_DIR from
  data/processed/sequences_leakage_safe to data/processed/sequences.
- src/dataset_cnn.py and scripts/train_cnn_1d.py, train_cnn_2d.py, cnn_*.py,
  train_home_away_hybrid.py: either migrate to canonical sequence files or
  mark as archived.
- tests/test_sequence_features.py: add a metadata/label/array alignment test
  and optionally a test that raw_plus_rolling feature names match X dimensions
  for home_away outputs.
- Optional new tests:
  - canonical sequence metadata target equals saved y for each split.
  - home/away history end dates are strictly before target date for saved
    metadata.
  - feature names length equals X.shape[-1] for home_away raw and raw_plus_rolling.

Files safe to remove later after migration:
- models/ml_models.py
- models/baseline_model.py
- data/processed/raw_sequence_engineering.py
- data/processed/sequence_engineering.py
- data/processed/split_for_ml.py
- src/dataset_cnn.py if no scripts still import it
- generated legacy artifacts under artifacts/ml_artifacts, artifacts/baseline,
  artifacts/cnn, data/processed/k_*_*.npz, and data/processed/sequences_leakage_safe
  if present.

Risks before deletion:
- Some CNN scripts still import src.dataset_cnn or src.raw_dataset_cnn. Deleting
  builders/loaders before migration will break those experiments.
- Existing reports may reference historical artifact names. Preserve reports or
  add a short archive note if reproducibility matters.
- Generated .npz files are absent in this checkout; run the canonical builders
  before validating migrated CNN scripts.
- Git status could not be checked because Git reports this repository as a
  dubious-ownership safe-directory issue under the current Windows user.


Final Recommendation
--------------------
Use src/models/ml_baselines.py for classical ML and src/features/sequences.py
for sequential data. The weaker/redundant ML baselines are the legacy
models/ml_models.py and models/baseline_model.py paths. The default sequence
dataset should be canonical raw home_away sequences from scripts/build_sequences.py.
Keep raw_plus_rolling optional, not default. Archive/remove the standalone raw
sequence builder and feature-derived CNN builder only after dependent CNN scripts
are migrated or explicitly retired.
